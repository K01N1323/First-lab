# Индивидуальное ТЗ. Лабораторная работа №1

Основа задания — `/Users/nikolaj/Downloads/ЛР-1.docx` и выбранный пользователем
набор возможностей. `ЛР-2-2.pdf` — методичка исходной второй лабораторной.

Реализовать на C++17 полиморфное бинарное дерево поиска на указателях.
Сохранить стиль исходного проекта `Second_Lab`, собственный динамический массив,
указатели на функции и ручное владение узлами. Шаблоны и тесты оформить в `.hpp`.

| Возможность | Рейтинг |
|---|---:|
| Вставка, поиск, удаление | 5 |
| Автоматическая AVL-балансировка | 2 |
| Map, Reduce, Where | 3 |
| Сохранение по строке форматирования | 3 |
| Чтение по фиксированному формату | 1 |
| Извлечение поддерева | 2 |
| Поиск полного поддерева | 3 |
| ICollection | 2 |
| IEnumerable и TreeEnumerator | 3 |
| Осмысленные операторы ==, !=, + | 2 |
| **Итого** | **26** |

Рейтинг общих интерфейсов учитывается один раз. Перечислитель не считается
прошивкой. Куча, трёхарное дерево, очередь с приоритетами и отдельное множество
в эту работу не входят.

`Insert` отклоняет дубликаты по компаратору. `Map` и `Where` возвращают независимые
деревья; `Map` восстанавливает порядок и отклоняет эквивалентные результаты.
`Reduce` работает по ЛКП с начальным значением и произвольным типом результата.
AVL-балансировка выполняется поворотами после каждой вставки и удаления.
Узлы хранят height, пустое поддерево имеет высоту 0, лист — 1.
Копирование и извлечение сохраняют форму и высоты. Поиск
поддерева и сравнение учитывают значения и наличие каждого потомка.

Сохранение поддерживает все шесть перестановок К, Л, П с ограничителями;
пустое поддерево обозначается явно. Чтение поддерживает только `{К}(Л)[П]`,
восстанавливает форму и высоты, проверяет BST, AVL, дубликаты и повреждения.
Несбалансированный BST и лишние данные отклоняются.
Строки с пробелами, кавычками и служебными символами должны читаться однозначно,
вещественные числа — с разумной точностью записи обычных конечных значений. Ошибки не оставляют
утечек и не повреждают существующее дерево.

В предоставленной методичке второй лабораторной отсутствуют определения
`ICollection` и `IEnumerable`. Принято допущение: минимальный `IEnumerable`
предоставляет существующий `GetEnumerator`, `ICollection` — доступ `Get` по индексу
ЛКП и `GetCount`. Сохраняется размер `int`; деструкторы интерфейсов виртуальные.
Контракт исходного `IEnumerator` не изменяется.

Консольное меню: типы int/double/string, ручное и автоматическое заполнение,
все выбранные операции, отдельное второе дерево, исходные данные и результаты,
вывод формы с ограничением объёма и корректное завершение по концу ввода.

Независимые наборы тестов покрывают базовые и граничные случаи, ошибки функций,
копирование, перемещение, исключения, четыре поворота, AVL-удаление,
возрастающую вставку, интерфейсы и пользовательский тип.
Сборка с предупреждениями, AddressSanitizer и UndefinedBehaviorSanitizer;
ошибки тестов возвращают ненулевой код.

Измерения: оптимизированная сборка, фиксированный seed, несколько размеров,
случайная и упорядоченная вставка; вставка, поиск и удаление. Повороты входят
в замер вставки/удаления, отдельного метода ручной балансировки нет.
Генерация, копирование контрольного дерева и вывод выполняются вне таймера.
Результаты проверяются и сохраняются в CSV; Python строит графики по фактическим
измерениям. Размеры 10⁶–10⁸ включаются отдельно
с заданными пределами. Верхняя граница фактических запусков фиксируется в отчёте.

Общие структуры сначала исправляются и проверяются в `Second_Lab`, затем
копируются в `First lab` с проверкой побайтового совпадения.
