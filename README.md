C++17, узлы на указателях, компаратор и функции через указатели на функции.
Исходный проект — локальный Second_Lab. Названия старых методов, оформление
конструкторов, условий, меню и тестов сохранены. Структуры и тесты находятся

## Сборка и запуск

```sh
make
./binary_search_tree
make test
make sanitize
make release
make performance
make graphs
make clean
```

Без аргументов — меню, --test — все тесты, --performance — измерения.

обычная и release-сборки используют -O2. make sanitize запускает тесты
с AddressSanitizer и UndefinedBehaviorSanitizer. C++-программа не требует
внешних библиотек; для графиков нужен Python с matplotlib.

## Автоматическая балансировка

В Node сохранены data, left, right, parent и добавлена только высота height.
Пустое поддерево имеет высоту 0, лист — 1. После вставки и удаления программа
поднимается через parent к корню, пересчитывает высоты и делает AVL-повороты.
Узлы не пересоздаются, данные не переставляются. Отдельного Balance нет.

| Метод | Назначение |
|---|---|
| GetHeight | Высота узла или 0 для nullptr |
| UpdateHeight | Большая высота ребёнка плюс 1 |
| RotateLeft | Поднять правого ребёнка, прежний корень опустить влево |
| RotateRight | Поднять левого ребёнка, прежний корень опустить вправо |
| BalanceNode | По разности высот выбрать один или два поворота |
| BalanceToRoot | Повторить пересчёт и балансировку до корня |

Например, после вставок 3, 2, 1 правый поворот даёт:

```text
    3             2
   /             / \
  2      ->     1   3
 /
1
```

Если тяжёлый ребёнок наклонён в противоположную сторону, сначала поворачивается
он, затем исходный узел. Нулевой баланс ребёнка при удалении требует одного
поворота. Повороты обновляют parent, детей, связь с прежним родителем и root.
В удалении узла с двумя детьми преемник отсоединяется из правого поддерева;
подъём начинается от его прежнего родителя. Если преемник был непосредственным
правым ребёнком удаляемого узла, подъём начинается от преемника.

## Операции

Insert отклоняет повтор по компаратору, Remove и GetSubtree — отсутствующий
элемент. Find возвращает указатель или nullptr. Get по индексу читает ЛКП.
Компаратор задаёт строгий слабый порядок; эквивалентность означает, что оба
направления сравнения возвращают false. Изменяемый Find сохранён: нельзя
менять через него значение, определяющее положение узла в дереве.

Map обходит исходное дерево, преобразует значение и вызывает result.Insert.
Where вставляет подходящие значения. Reduce идёт по ЛКП с начальным значением,
тип аккумулятора может отличаться от T. Пустые функции вызывают исключение.
Коллизия результатов Map отклоняется обычным Insert. Исключение освобождает
частичный результат, исходное дерево сохраняется.

Оператор + вставляет значения обоих деревьев, пропуская уже присутствующие.
Используется компаратор левого дерева. GetSubtree создаёт независимую копию
с той же формой и высотами; parent нового корня — nullptr. ==, != и
ContainsSubtree учитывают значения и всю форму, включая отсутствующих детей.
Пустое дерево входит в любое. Для операций над двумя деревьями нужен совместимый
порядок компараторов. Копирование сохраняет высоты, перемещение передаёт готовое
дерево. После перемещения источник можно использовать снова.

## Сохранение и чтение

ToString по умолчанию использует {К}(Л)[П]:

```text
{1:2}({1:1}(#)[#])[{1:3}(#)[#]]
```

# — пустое поддерево. Значение записано как длина:значение, длина в байтах.
Строки сохраняются буквально, включая пробелы, кавычки и служебные символы.
Числа читаются обычными строковыми потоками. Double записывается с max_digits10.
Демонстрации рассчитаны на обычные конечные числа; специальных ветвей обработки
особых числовых значений и принудительной настройки локали нет.

Поддерживаются все шесть перестановок К, Л, П. Каждый маркер может быть без
ограничителей или с двумя ограничителями: слева { ( [ <, справа } ) ] >.
Ограничители могут различаться, как в пояснении ТЗ. Примеры:

```text
{К}(Л)[П]   {К}[П](Л)   (Л){К}[П]
(Л)[П]{К}   [П]{К}(Л)   [П](Л){К}   {Л]К[П}
```

FromString читает только {К}(Л)[П]. Во временном дереве восстанавливаются форма,
parent, размер и высоты. Проверяются запись, значения, порядок BST, дубликаты,
AVL-баланс и отсутствие лишних данных. Правильный BST с нарушенным AVL-балансом
отклоняется. Ошибка не повреждает прежнее дерево. Разбор и освобождение частичного
дерева итеративные; сохранение и сравнение используют небольшую рекурсию по AVL.
Текстовые требования возникают только при вызове методов ввода и вывода.

## Меню и интерфейсы

Типы: int, double, std::string. Доступны ручной ввод, генерация с количеством,
диапазоном или префиксом, seed и порядком вставки, основные операции, функции,
поддеревья, сохранение, чтение, сравнение, объединение, тесты и измерения.
Второе дерево задаётся в пункте 12; проверка вхождения — 13, объединение — 16.
Пункта ручной балансировки нет: вставка и удаление уже поддерживают AVL.

Print показывает форму с К/Л/П и #, по умолчанию до 60 узлов/пустых детей.
Длина строк и глубина отдельно не ограничиваются. Меню выводит до 4000 байтов
сериализации; полная запись доступна при сохранении в файл. Генерация ограничена
миллионом элементов для обоих порядков. Длины строк считаются в байтах UTF-8.
Числовой ввод оформлен как в исходном ReadInt/ReadChoice. EOF завершает программу.
Проверки переполнения целых в демонстрационных функциях сохранены.

IEnumerator оставлен без изменений; GetEnumerator всегда обходит ЛКП.
IEnumerable предоставляет GetEnumerator, ICollection — Get и GetCount.
В методичке ЛР-2-2.pdf нет их определений, поэтому оставлен прежний минимальный
контракт. Деструкторы виртуальные. Перечислитель удаляет вызывающий код;
после изменения дерева его следует создать заново.

## Сложности

Стоимость сравнения и пользовательской функции считается постоянной.

| Операция | Время | Дополнительная память |
|---|---|---|
| Insert, Find, Remove | O(log n) | O(1) |
| Серия n возрастающих вставок | O(n log n) | O(n) для узлов |
| Map, Where | O(n log n) | O(n) для результата |
| Reduce, полный обход, Get по индексу | O(n) | O(1), кроме аккумулятора |
| + | O((n + m) log(n + m)) | O(n + m) для результата |
| GetSubtree | O(log n + k) | O(k) для копии |
| ContainsSubtree | O(log n + k) | O(log n) для сравнения |
| Копирование, Clear | O(n) | O(n) для копии / O(1) для Clear |
| ==, != | O(n) | O(log n) |
| ToString, FromString | O(n + число байтов) | Запись / новые узлы |

Сложность Reduce также зависит от стоимости работы с аккумулятором. Ввод
некорректной цепочки может использовать O(n) памяти до обнаружения нарушения AVL.

## Измерения

```sh
make performance
make performance PERFORMANCE_ARGS="--max 100000 --ordered-limit 100000 --repeats 3 --csv docs/performance-avl.csv"
make graphs
```

Измеряются вставка, поиск и удаление; повороты входят во время Insert/Remove.
Отдельного измерения Balance больше нет. Порядки — случайный и возрастающий,
seed 1323, по три повтора. Генерация, копирование, проверки и вывод вне таймера.
Поиск: n успешных и n неуспешных запросов. Результаты проверяются по размерам
и контрольным суммам. По умолчанию максимум 100000 для обоих порядков.
Существующие --max, --ordered-limit, --repeats, --seed, --csv сохранены.

Новые данные: docs/performance-avl.csv. Графики: docs/graphs/performance-avl.png
и .svg. Прежние performance.csv и performance.png/.svg сохранены как история
предыдущей реализации и не считаются измерениями AVL. Миллионные замеры повторно
не выполнялись. Текущие проверки: [docs/Verification.md](docs/Verification.md).
